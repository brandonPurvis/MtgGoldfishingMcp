# Tools — Specs

Design: `tools-design.md`. Prefix: `TOOL`.

## Serving

- [x] **TOOL-001**: The service shall serve MCP over streamable HTTP in stateless mode at the path `/mcp` of a FastAPI application, under the MCP server name `goldfishing`.
- [x] **TOOL-002**: When `GET /health` is requested, the service shall respond with a success status.
- [x] **TOOL-003**: The service shall listen on the address in `MTG_GOLDFISHING_HOST`, defaulting to `127.0.0.1`, and the port in `MTG_GOLDFISHING_PORT`, defaulting to `8000`.
- [x] **TOOL-004**: The service shall keep its database at the path in `MTG_GOLDFISHING_DB`, defaulting to `data/mtg-goldfishing.sqlite3`.
- [x] **TOOL-005**: The command `uv run mtg-goldfishing` shall start the service.
- [x] **TOOL-006**: The repository shall carry a `.mcp.json` that connects Claude Code to `http://127.0.0.1:8000/mcp` under the server name `goldfishing`.

## Tool surface

- [x] **TOOL-007**: The MCP adapter shall expose exactly the tools `load_deck`, `new_game`, `mulligan`, `get_state`, `play`, `effect`, `choose`, `attack`, `advance`, `pass`, `wait`, `end_game` and `get_log`.
- [x] **TOOL-008**: Every game-scoped tool (every tool but `load_deck` and `new_game`) shall take `game_id` as its first parameter.
- [x] **TOOL-009**: Each of `mulligan`, `play`, `effect`, `choose`, `attack`, `advance` and `end_game` shall accept an optional `after` parameter.
- [x] **TOOL-010**: When an object or list parameter (`delta`, `choices`, `pay`, `expect`, `selections`, `definitions`) is given as a JSON string, the MCP adapter shall parse the string and use the result.
- [x] **TOOL-011**: Each tool description, whatever kind of game the tool serves, shall state, in order, the tool's purpose in one sentence, what the service does automatically as a result, each parameter's meaning with an example value, and what can be overridden.
- [x] **TOOL-012**: The MCP server's instructions shall describe, for every game: loading a deck once and starting games on it; mulligans; the shape of a turn; stating what a card does in a delta; overriding a `REJECTED` response; answering a `CHOICE` response with `choose`; why `advance` may stop early; the status line; passing the change number as `after`; and ending the game.
- [x] **TOOL-013**: The MCP adapter shall contain no rule of play and shall reach the service only by calling use cases.
- [x] **TOOL-031**: The `game_id` parameter of every game-scoped tool shall carry the calling seat's seat id (the id `new_game` gave that seat); the tested seat's seat id is the game id, so every call of a goldfish game passes its game id, and no tool shall have a separate `seat_id` parameter.
- [x] **TOOL-032**: `pass` shall accept an optional `after` parameter (the change number the calling seat last saw), as every other tool that changes a game does.
- [ ] **TOOL-033**: When a tool behaves differently or takes a parameter only in a contested game, its description shall state that in a final sentence or parameter entry marked `Contested games:`, after everything that applies to a goldfish game.
- [x] **TOOL-069**: The `Contested games:` part of the `effect` description shall say that an `effect` with `immediate: true` stating the result of combat between creatures gives only what happens to the creatures, because the service deals the declared attack's damage to seats on entering `combat_damage` and a `life` or `damage` entry for that same damage would be applied in addition to it.
- [x] **TOOL-070**: The `Contested games:` part of the `attack` description shall say that a `damage` entry for a blocked attacker is dealt in full to the seat it attacks, the service making no reduction for blockers, so the entry is the attacking seat's statement of the damage that gets past them.
- [x] **TOOL-071**: The `Contested games:` part of the `attack` description shall say that an `attack` may stop before attackers are declared, at a step where another seat has a reminder, that nothing is then declared or tapped, and that the attacking seat sends `attack` again once it is the seat to act.
- [ ] **TOOL-034**: The MCP server's instructions shall continue, after the guide for every game, with a section on contested games describing: that `new_game` with `opponents` starts a contested game and returns one seat id per seat, which each seat's agent passes as `game_id`; that seats act one at a time and a seat that is not the seat to act calls `wait`; that spells and abilities go on the stack and resolve once every other seat has passed, and that a seat asked to respond uses `play`, `effect` or `pass`; that a `CHOICE` addressed to a seat (blocks, a decision another seat's effect asks of it, or whether a spell still does what was stated) is answered with `choose`; that after blocks the attacking seat states what happens to the creatures with `effect` and `immediate: true` while the service deals the damage to seats; that each response begins with what the other seats did since the seat's last call; and that only the tested seat ends the game while an opposing seat's `end_game` concedes.

## Response format

- [x] **TOOL-014**: In every game, every tool except a successful `get_log` shall respond with a single text item made of, in order, a status-and-summary line, zero or more event lines, and, for a response about an existing game, a status line; only the digest lines of a contested game (TOOL-035) may come before the status-and-summary line.
- [x] **TOOL-015**: The first word of a text response's status-and-summary line shall be `OK`, `REJECTED`, `ERROR` or `CHOICE`; in a goldfish game, and in any response with no digest lines, that line is the first line of the response.
- [x] **TOOL-016**: In a goldfish game, event lines shall appear in this order when present: a statement that the call was already applied; overridden rule checks; steps entered; payment; moves, tokens created and cards drawn; cards revealed for a pending choice with its choice id; combat damage per attacker; assumptions; reminders; why an advance stopped; expectation warnings; notices.
- [x] **TOOL-017**: The status line for a started goldfish game shall read `T<turn> <step> · Hand <n> · Lands <n> (<n> untapped) · Pool <mana> · Life <n> · Dmg <n>/120 · Cmdr <a>/<b>/<c> · Tax <n> · #<change>`, where `Cmdr` shows that commander's damage to each of the three imaginary opponents and an empty pool reads `{}`.
- [x] **TOOL-018**: While the seat of a goldfish game has two commanders, the status line shall show `Cmdr` and `Tax` as one group per commander separated by `|`, in the commanders' name order.
- [x] **TOOL-019**: While a goldfish game has no step (its status is `mulligan`, or it ended before the hand was kept), the status line shall read `Mulligan <k> · Hand <n> · #<change>`, where `<k>` is the number of mulligans taken.
- [x] **TOOL-020**: While a goldfish game has a pending choice, the status line shall end with ` · CHOICE pending`.
- [x] **TOOL-021**: While the status of a game, goldfish or contested, is `ended`, the status line shall begin with `Ended (<result>) · `.
- [x] **TOOL-022**: When a response does not concern an existing game (a `load_deck` response, or a call whose id names no game or seat), the response shall have no status line.
- [x] **TOOL-023**: When a response is `REJECTED`, in any game, its summary shall say what failed and that the call can be resubmitted with `override`.
- [x] **TOOL-024**: While a game, goldfish or contested, has raised notices, every text response about that game, to whichever seat, shall include them, whatever the response's status.
- [x] **TOOL-025**: In every game, a response to `play`, `effect`, `attack` or `advance` shall not list the full hand or the full battlefield.
- [x] **TOOL-026**: All response text, of every game, shall be produced by one renderer from a use case's outcome, with one rendering per event type.
- [x] **TOOL-035**: In a contested game, a text response to a seat shall begin, before its status-and-summary line, with one digest line for each element of the outcome's digest (the changes other seats made since that seat's previous response that carried a digest), oldest first.
- [x] **TOOL-036**: Each digest line of a contested game's response shall read `S<seat number> #<change number>: <events>`, naming the seat that made the change (the seat whose call it was), with everything that one change caused listed on that one line separated by `;`, including what it caused for other seats (an automatic pass for another seat, the resolution of another seat's stack item), so that a change number appears on at most one digest line.
- [x] **TOOL-057**: Within a digest line, every seat shall be named as `S<n>`, the calling seat included (`S3 drew Forest` on a line read by seat 3), and never as `you`.
- [x] **TOOL-037**: A digest line shall render the events of its digest element exactly as the outcome holds them (the public form: for example another seat's draw shown as a count, a pending choice shown by its kind and the seat it is addressed to; or the calling seat's own form of the change, APP-081, which names each card another seat's call moved into, between or out of the calling seat's own hand or library) and shall add no card name the element does not hold.
- [x] **TOOL-064**: A digest line shall render the public form of a mulligan taken as the seat and the number of mulligans it has now taken (`S2 took a mulligan (2 taken)`), and the public form of a kept hand as the seat and the numbers of cards kept and bottomed (`S2 kept 6, bottomed 1`).
- [x] **TOOL-065**: A digest line shall render the public form of a `hand` pending choice as the seat it is addressed to and the seat whose hand is shown (`S3 looks at S1's hand (CHOICE hand)`), naming none of the cards.
- [x] **TOOL-038**: When the outcome's digest is empty because no other seat has made a change since the calling seat's previous response that carried a digest, a contested game's response shall have no digest lines.
- [x] **TOOL-056**: A successful `get_log` response, in a contested game as in a goldfish game, shall be JSON alone, with no digest lines before it.
- [x] **TOOL-039**: A response of a goldfish game shall never have digest lines, a `Stack` field, an `Act` field or any line about a stack item, response window or automatic pass.
- [x] **TOOL-040**: In a contested game, event lines shall appear in this order when present: what the calling seat is now asked to do, when it is a seat to act (for example `You are asked to respond to s4: Counterspell from S3.`); a statement that the call was already applied; overridden rule checks; steps entered; payment; moves, tokens created and cards drawn; cards revealed for a pending choice with its choice id; combat damage per attacker; assumptions; reminders; why an advance stopped; expectation warnings; items put on the stack; automatic passes; resolutions and counters; eliminations; notices.
- [x] **TOOL-041**: The status line of a started contested game, as the calling seat sees it, shall read `T<turn> <step> (S<active>) · You S<n> · Hand <n> · Lands <n> (<n> untapped) · Pool <mana> · Life <n> · S<n> <life> ... · Cmdr <dmg>/... · Tax <n> · Stack <n> · Act <who> <what> · #<change>`, where `Hand`, `Lands`, `Pool`, `Life` and `Tax` are the calling seat's own and an empty pool reads `{}`.
- [x] **TOOL-058**: While the calling seat of a contested game has two commanders, the status line shall show `Tax` as one number per commander separated by `|`, and shall order the `|` groups of both `Cmdr` and `Tax` by the commanders' names, as a goldfish game's line does.
- [x] **TOOL-059**: A contested game's status line shall never end with ` · CHOICE pending`: a waiting pending choice is shown by `Act`, which names the seat it is addressed to and the choice's kind.
- [x] **TOOL-042**: In a contested game's status line, `T<turn>` shall be the number of turns the calling seat has begun, not the table turn number, and `(S<active>)` shall name the active seat by seat number.
- [x] **TOOL-043**: In a contested game's status line, `You S<n>` shall give the calling seat's seat number.
- [x] **TOOL-044**: A contested game's status line shall show one `S<n> <life>` group for each seat other than the calling seat, in ascending seat number (for calling seat 3 of four: `S1`, `S2`, `S4`), with `out` in place of the life of an eliminated seat.
- [x] **TOOL-045**: In a contested game's status line, `Cmdr` shall show the combat damage the calling seat's commander has dealt to each other seat, one number per `S<n> <life>` group and in the same order, separated by `/`, an eliminated seat keeping its number so that positions match the life groups; while the calling seat has two commanders it shall show one such group per commander separated by `|`.
- [x] **TOOL-046**: A contested game's status line shall show `Stack <n>`, the number of items on the stack, only while the stack is not empty.
- [x] **TOOL-047**: In a contested game's status line, `Act` shall name the seat to act (the seat whose call the game is waiting on), as `you` when it is the calling seat and as `S<n>` otherwise, followed by one word for what that seat is asked, for example `Act you respond`, `Act S3 blocks`, `Act S2 turn`.
- [x] **TOOL-060**: The word after the seat in a started contested game's `Act` shall be exactly one of: the kind of the waiting pending choice the seat must answer (`look`, `search`, `hand`, `ask`, `resolve` or `blocks`); `trigger` when a reminder waits for it as a seat other than the active seat; `respond` when a response window is asking it; `turn` when it is the active seat and none of the others holds, whatever the step and whether or not a discard is owed.
- [x] **TOOL-061**: The sentence that says what a seat is asked, in the first event line of TOOL-040 (`You are asked to ...`) and in the `ERROR` summary of TOOL-050 (`S<n> is asked to ...`), shall be, by the `Act` word of TOOL-060: for `respond`, `respond to <stack item id>` in a `stack` response window (the event line adding `: <source> from S<controller>`), `respond to the attack` in an `attack` window and `respond in the end step` in an `end` window; for `trigger`, `record or pass the <step> trigger of <card names>`; for a pending choice, `answer the <kind> choice`; for `turn`, `take its turn` (`take your turn` to the seat itself); and during mulligans `keep or mulligan`.
- [x] **TOOL-048**: While a contested game has no step because seats are still taking mulligans, the status line shall read `Mulligan <k> · Hand <n> · Act <seats> · #<change>`, where `<k>` and `<n>` are the calling seat's mulligans taken and hand size and `<seats>` names every seat that has not yet kept, in ascending seat number, separated by single spaces, the calling seat as `you` and every other as `S<n>`, with no word after them (`Mulligan 1 · Hand 7 · Act you S3 · #4`).
- [x] **TOOL-049**: While the calling seat of a contested game is eliminated, the status line of its responses shall begin with `Out · `, which comes after the `Ended (<result>) · ` of TOOL-021 once the game has also ended (`Ended (win) · Out · T6 ...`).
- [x] **TOOL-062**: While a contested game's status is `ended`, its status line shall be the line of TOOL-041, or of TOOL-048 when the game ended during mulligans, after the `Ended (<result>) · ` prefix, with the `Act` field and the `Stack` field left out, no seat being asked and the stack having been discarded.
- [x] **TOOL-063**: When `wait` returns on timeout, the response's summary shall read `OK Still waiting: ` followed by the seat to act and what it is asked in the wording of TOOL-061 (`OK Still waiting: S3 is asked to respond to s4.`), and during mulligans shall name every seat still to keep.
- [x] **TOOL-050**: When a call to a contested game comes from a seat that may not make that call now because it is not the seat to act, the `ERROR` summary shall name the seat to act by seat number, say what that seat is asked, and suggest calling `wait`, for example `ERROR Not your seat's call: S3 is asked to respond to s4. Call wait to be told when it is yours.`
- [x] **TOOL-051**: A text response to a seat of a contested game, its `get_state` listing included, shall be rendered from the outcome's game summary for that calling seat alone, and so shall show no card of another seat's hand and no card of any library.
- [x] **TOOL-066**: In a contested game's `get_state` listing, a permanent whose controller is not its owner shall be listed on its controller's battlefield with ` (owner S<n>)` after its name, and a permanent its controller owns shall carry no owner mark.
- [x] **TOOL-067**: When a call to a contested game gives an instance id of a card in another seat's hand or library (GAME-157), the `ERROR` summary shall read `ERROR <instance id> is in a hidden zone of S<n>.`, followed, for a delta, by the hint that other seats' hands and libraries are reached through `ask`, and shall name neither the card nor which of the two zones holds it.
- [x] **TOOL-068**: When a card name given in a contested game matches nothing the calling seat may see (GAME-156), the `ERROR` summary shall be word for word the same whether or not another seat holds a card of that name in its hand or library.

## MCP details

- [x] **TOOL-027**: In every game, when a response's status is `ERROR`, the MCP result shall set its error flag; when the status is `OK`, `REJECTED` or `CHOICE`, it shall not.
- [x] **TOOL-028**: If a tool call's arguments are missing, of the wrong type or otherwise malformed, then the MCP adapter shall respond in the text `ERROR` format rather than with a protocol-level fault, and a call record shall be stored for the call. An argument name the tool does not have is malformed. A call naming a tool that does not exist is answered as a protocol error.

## Player brief

- [x] **TOOL-029**: The repository shall carry one player brief for every seat of every game, a Claude Code subagent definition at `.claude/agents/goldfish-player.md`, that restricts the subagent to the `goldfishing` server's tools.
- [x] **TOOL-030**: The player brief shall instruct the subagent, for every game, to play as a strong player aiming to win as fast as the deck can, make every decision itself, give a `reason` on non-obvious plays, use `expect` on plays where it is tracking a number closely, pass `after` on every changing call, resolve or consciously pass reminders, end the game with `end_game` and a verdict, and return the game id, seed and verdict.
- [ ] **TOOL-052**: The player brief shall state that the subagent is given a deck id or a deck list to load, and optionally a seed and a turn limit, or instead, for a contested game, a seat id and which seat it plays.
- [ ] **TOOL-053**: The player brief shall have a section on contested games instructing the subagent to: play its seat to win unless its instructions give it another goal; call `wait` whenever its seat is not the seat to act and act on what `wait` returns; read the digest at the top of each response; respond with `play` or `effect` when asked and it has something worth doing, and `pass` otherwise; answer pending choices addressed to it, including blocks and decisions other seats' effects ask of it; and, when attacking, state what happens to the creatures with `effect` and `immediate: true` after blocks.
- [ ] **TOOL-072**: The player brief's section on contested games shall instruct the subagent, when it states the result of combat with `effect` and `immediate: true`, to leave out the combat damage dealt to seats, which the service deals itself, and to give `damage` on `attack` for a blocked attacker only for damage that gets past its blockers.
- [ ] **TOOL-073**: The player brief's section on contested games shall instruct the subagent, when an `attack` response says the attack was not declared, to call `wait` and then send the same `attack` again.
- [ ] **TOOL-054**: The player brief's section on contested games shall instruct the subagent, as the tested seat, to end the game with `end_game` and a verdict that names what the opposition did to the deck, and, as an opposing seat, to concede with `end_game` when it is beaten and otherwise play until the game ends.
- [ ] **TOOL-055**: The player brief's section on contested games shall instruct a subagent that was given an id and a seat to play, rather than a deck to start a game on, to return as its final message its seat number, the id it was given (the game id for the tested seat, its own seat id for an opposing seat) and its verdict, in place of the game id, seed and verdict of TOOL-030, since such a subagent is never shown the seed.
