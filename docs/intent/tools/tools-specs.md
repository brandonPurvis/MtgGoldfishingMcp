# Tools — Specs

Design: `tools-design.md`. Prefix: `TOOL`.

## Serving

- [x] **TOOL-001**: The service shall serve MCP over streamable HTTP in stateless mode at the path `/mcp` of a FastAPI application, under the MCP server name `goldfishing`.
- [x] **TOOL-002**: When `GET /health` is requested, the service shall respond with a success status.
- [x] **TOOL-003**: The service shall listen on the address in `MTG_GOLDFISHING_HOST`, defaulting to `127.0.0.1`, and the port in `MTG_GOLDFISHING_PORT`, defaulting to `8000`.
- [x] **TOOL-004**: The service shall keep its database at the path in `MTG_GOLDFISHING_DB`, defaulting to `data/mtg-goldfishing.sqlite3`.
- [x] **TOOL-005**: The command `uv run mtg-goldfishing` shall start the service.
- [x] **TOOL-006**: The repository shall carry a `.mcp.json` that connects Claude Code to `http://127.0.0.1:8000/mcp` under the server name `goldfishing`.

## Tool surface

- [x] **TOOL-007**: The MCP adapter shall expose exactly the tools `load_deck`, `new_game`, `mulligan`, `get_state`, `play`, `effect`, `choose`, `attack`, `advance`, `pass`, `wait`, `end_game` and `get_log`.
- [x] **TOOL-008**: Every game-scoped tool (every tool but `load_deck` and `new_game`) shall take `game_id` as its first parameter.
- [x] **TOOL-009**: Each of `mulligan`, `play`, `effect`, `choose`, `attack`, `advance` and `end_game` shall accept an optional `after` parameter.
- [x] **TOOL-010**: When an object or list parameter (`delta`, `choices`, `pay`, `cast_triggers`, `expect`, `selections`, `definitions`) is given as a JSON string, the MCP adapter shall parse the string and use the result; a value inside such a parameter, such as a cast trigger's `delta`, is not parsed from a string again.
- [ ] **TOOL-107**: When `get_state`'s `card` is given as a text that parses as a JSON list, the MCP adapter shall parse it and use the list, as for the list parameters of TOOL-010; any other text shall be taken as one card name or instance id.
- [x] **TOOL-011**: Each tool description, whatever kind of game the tool serves, shall state, in order, the tool's purpose in one sentence, what the service does automatically as a result, each parameter's meaning with an example value, and what can be overridden.
- [x] **TOOL-012**: The MCP server's instructions shall describe, for every game: loading a deck once and starting games on it; mulligans; the shape of a turn; stating what a card does in a delta; overriding a `REJECTED` response; answering a `CHOICE` response with `choose`; why `advance` may stop early; the status line; passing the change number as `after`; and ending the game.
- [x] **TOOL-013**: The MCP adapter shall contain no rule of play and shall reach the service only by calling use cases.
- [x] **TOOL-031**: The `game_id` parameter of every game-scoped tool shall carry the calling seat's seat id (the id `new_game` gave that seat); the tested seat's seat id is the game id, so every call of a goldfish game passes its game id, and no tool shall have a separate `seat_id` parameter.
- [x] **TOOL-032**: `pass` shall accept an optional `after` parameter (the change number the calling seat last saw), as every other tool that changes a game does.
- [x] **TOOL-033**: When a tool behaves differently or takes a parameter only in a contested game, its description shall state that in a final sentence or parameter entry marked `Contested games:`, after everything that applies to a goldfish game.
- [x] **TOOL-069**: The `Contested games:` part of the `effect` description shall say that an `effect` with `immediate: true` stating the result of combat between creatures gives only what happens to the creatures, because the service deals the declared attack's damage to seats on entering `combat_damage` and a `life` or `damage` entry for that same damage would be applied in addition to it.
- [x] **TOOL-070**: The `Contested games:` part of the `attack` description shall say that a blocked attacker deals no combat damage to the seat it attacks, its `damage` entry included, unless the attacking seat states its trample damage, once blocks are known and before combat damage, with an `attack` that gives `trample` and no `attackers`.
- [x] **TOOL-076**: The `Contested games:` part of the `attack` description shall say that `evasion` states, per attacker, flying, horsemanship or "can't be blocked" (`unblockable`) that the attacker has beyond what the service has read, for that declaration only, and that a block the attacker's evasion forbids is refused as a rule check.
- [x] **TOOL-077**: The `Contested games:` part of the `choose` description shall say that a `blocks` answer fails a rule check when the attacker's flying, horsemanship or "can't be blocked" forbids a block, and that a blocker with flying or reach only for this turn blocks with an `override` giving that reason.
- [x] **TOOL-081**: The `play` description shall describe `cast_triggers` in its parameter entries, for every game: the casting seat's own triggers on casting the spell, each an object with `source`, `delta` and optional `choices`, with one example value of the whole parameter, resolving before the spell in the order listed with the first listed first, and taken by no land.
- [x] **TOOL-082**: The `Contested games:` part of the `play` description shall say that cast triggers go on the stack above the spell before any seat is asked, and that they are stated in the `play` itself because a spell no other seat can answer resolves within that call.
- [x] **TOOL-083**: The `Contested games:` part of the `choose` description shall say that an `ask` answer may carry `text`, the answer text (the card named, the guess, the number), which every seat is shown and which is recorded and never judged, that it holds at most 200 characters, and that it is accepted for no other kind of pending choice.
- [ ] **TOOL-098**: The `get_state` description shall describe `card`, for every game: a card name or instance id, or a list of them, with one example value, whose rules text the response gives in place of the listing, only for cards the calling seat may see, and which is not given together with `detail`.
- [ ] **TOOL-099**: The `Contested games:` part of the `wait` description shall say that an answer saying the seat is still waiting means only that the seat to act has not yet acted, and that the calling seat then calls `wait` again.
- [x] **TOOL-071**: The `Contested games:` part of the `attack` description shall say that an `attack` may stop before attackers are declared, at a step where another seat has a reminder, that nothing is then declared or tapped, and that the attacking seat sends `attack` again once it is the seat to act.
- [x] **TOOL-034**: The MCP server's instructions shall continue, after the guide for every game, with a section on contested games describing: that `new_game` with `opponents` starts a contested game and returns one seat id per seat, which each seat's agent passes as `game_id`; that seats act one at a time and a seat that is not the seat to act calls `wait`; that spells and abilities go on the stack and resolve once every other seat has passed, and that a seat asked to respond uses `play`, `effect` or `pass`; that a `CHOICE` addressed to a seat (blocks, a decision another seat's effect asks of it, or whether a spell still does what was stated) is answered with `choose`; that after blocks the attacking seat states what happens to the creatures with `effect` and `immediate: true` while the service deals the damage to seats; that each response begins with what the other seats did since the seat's last call; and that only the tested seat ends the game while an opposing seat's `end_game` concedes.
- [x] **TOOL-078**: The contested-games section of the MCP server's instructions shall say that a blocked attacker deals the seat it attacks no combat damage unless the attacking seat states its trample damage with `attack` and `trample` before combat damage.
- [x] **TOOL-084**: The contested-games section of the MCP server's instructions shall say that a seat states its own "whenever you cast" triggers as `cast_triggers` in the `play` that casts the spell, because a spell no other seat can answer resolves within that call.
- [ ] **TOOL-100**: The MCP server's instructions shall say, in the guide for every game, that an agent unsure what a card does reads its rules text with `get_state` and `card` rather than relying on memory.
- [ ] **TOOL-101**: The contested-games section of the MCP server's instructions shall say that, until the game ends or its seat is eliminated, a seat calls `wait` again after every answer that says it is still waiting, however long, because another seat taking its time is not a stalled game.
- [ ] **TOOL-102**: The contested-games section of the MCP server's instructions shall say that `wait` answers within its `timeout`, 30 seconds unless one is given and at most 60, and that an agent leaves `timeout` at its default unless its client is known to wait longer than 60 seconds for a call.
- [ ] **TOOL-108**: The contested-games section of the MCP server's instructions shall say that a `wait` that fails or comes back empty means the agent's client stopped waiting, not that the game stalled, and that the agent calls `wait` again.
- [x] **TOOL-085**: The contested-games section of the MCP server's instructions shall say that when an `ask` has a seat name a card, guess or choose a number, the seat gives it as `text` in its `choose`, and that every seat sees it.

## Response format

- [x] **TOOL-014**: In every game, every tool except a successful `get_log` shall respond with a single text item made of, in order, a status-and-summary line, zero or more event lines, and, for a response about an existing game, a status line; only the digest lines of a contested game (TOOL-035) may come before the status-and-summary line.
- [x] **TOOL-015**: The first word of a text response's status-and-summary line shall be `OK`, `REJECTED`, `ERROR` or `CHOICE`; in a goldfish game, and in any response with no digest lines, that line is the first line of the response.
- [x] **TOOL-016**: In a goldfish game, event lines shall appear in this order when present: a statement that the call was already applied; overridden rule checks; steps entered; payment; cast triggers applied (TOOL-086); moves, tokens created and cards drawn; cards revealed for a pending choice with its choice id; combat damage per attacker; assumptions; reminders; why an advance stopped; expectation warnings; notices.
- [x] **TOOL-017**: The status line for a started goldfish game shall read `T<turn> <step> · Hand <n> · Lands <n> (<n> untapped) · Pool <mana> · Life <n> · Dmg <n>/120 · Cmdr <a>/<b>/<c> · Tax <n> · #<change>`, where `Cmdr` shows that commander's damage to each of the three imaginary opponents and an empty pool reads `{}`.
- [x] **TOOL-018**: While the seat of a goldfish game has two commanders, the status line shall show `Cmdr` and `Tax` as one group per commander separated by `|`, in the commanders' name order.
- [x] **TOOL-019**: While a goldfish game has no step (its status is `mulligan`, or it ended before the hand was kept), the status line shall read `Mulligan <k> · Hand <n> · #<change>`, where `<k>` is the number of mulligans taken.
- [x] **TOOL-020**: While a goldfish game has a pending choice, the status line shall end with ` · CHOICE pending`.
- [x] **TOOL-021**: While the status of a game, goldfish or contested, is `ended`, the status line shall begin with `Ended (<result>) · `.
- [x] **TOOL-022**: When a response does not concern an existing game (a `load_deck` response, or a call whose id names no game or seat), the response shall have no status line.
- [x] **TOOL-023**: When a response is `REJECTED`, in any game, its summary shall say what failed and that the call can be resubmitted with `override`.
- [x] **TOOL-024**: While a game, goldfish or contested, has raised notices, every text response about that game, to whichever seat, shall include them, whatever the response's status.
- [x] **TOOL-025**: In every game, a response to `play`, `effect`, `attack` or `advance` shall not list the full hand or the full battlefield.
- [x] **TOOL-026**: All response text, of every game, shall be produced by one renderer from a use case's outcome, with one rendering per event type.
- [x] **TOOL-035**: In a contested game, a text response to a seat shall begin, before its status-and-summary line, with one digest line for each element of the outcome's digest (the changes other seats made since that seat's previous response that carried a digest), oldest first.
- [x] **TOOL-036**: Each digest line of a contested game's response shall read `S<seat number> #<change number>: <events>`, naming the seat that made the change (the seat whose call it was), with everything that one change caused listed on that one line separated by `;`, including what it caused for other seats (an automatic pass for another seat, the resolution of another seat's stack item), so that a change number appears on at most one digest line.
- [x] **TOOL-057**: Within a digest line, every seat shall be named as `S<n>`, the calling seat included (`S3 drew Forest` on a line read by seat 3), and never as `you`.
- [x] **TOOL-037**: A digest line shall render the events of its digest element exactly as the outcome holds them (the public form: for example another seat's draw shown as a count, a pending choice shown by its kind and the seat it is addressed to; or the calling seat's own form of the change, APP-081, which names each card another seat's call moved into, between or out of the calling seat's own hand or library) and shall add no card name the element does not hold.
- [x] **TOOL-064**: A digest line shall render the public form of a mulligan taken as the seat and the number of mulligans it has now taken (`S2 took a mulligan (2 taken)`), and the public form of a kept hand as the seat and the numbers of cards kept and bottomed (`S2 kept 6, bottomed 1`).
- [x] **TOOL-065**: A digest line shall render the public form of a `hand` pending choice as the seat it is addressed to and the seat whose hand is shown (`S3 looks at S1's hand (CHOICE hand)`), naming none of the cards.
- [x] **TOOL-086**: In a goldfish game, the response to a `play` that states cast triggers shall carry one event line per cast trigger, in the order the triggers are listed, reading `Cast trigger: <source>.`
- [x] **TOOL-087**: In a contested game, the answer to an `ask` pending choice shall be rendered, in the answering seat's response and in every other seat's digest line, as `S<n> answered choice <choice id> (ask)` followed, when the answer carries answer text, by `: "<answer text>"` with the text as the game holds it, written verbatim with any quotation mark or backslash in it unescaped, the line's closing punctuation following as for every other event.
- [x] **TOOL-038**: When the outcome's digest is empty because no other seat has made a change since the calling seat's previous response that carried a digest, a contested game's response shall have no digest lines.
- [x] **TOOL-056**: A successful `get_log` response, in a contested game as in a goldfish game, shall be JSON alone, with no digest lines before it.
- [x] **TOOL-039**: A response of a goldfish game shall never have digest lines, a `Stack` field, an `Act` field or any line about a stack item, response window or automatic pass.
- [x] **TOOL-040**: In a contested game, event lines shall appear in this order when present: what the calling seat is now asked to do, when it is a seat to act (for example `You are asked to respond to s4: Counterspell from S3.`); a statement that the call was already applied; overridden rule checks; steps entered; payment; moves, tokens created and cards drawn; cards revealed for a pending choice with its choice id; combat damage per attacker; assumptions; reminders; why an advance stopped; expectation warnings; items put on the stack; automatic passes; resolutions and counters; eliminations; notices.
- [ ] **TOOL-041**: The status line of a started contested game, as the calling seat sees it, shall read `T<turn> <step> (S<active>) · You S<n> · Hand <n> · Lands <n> (<n> untapped) · Pool <mana> · Life <n> · S<n> <life> ... · Cmdr <dmg>/... · Cmdr taken <dmg>/... · Tax <n> · Stack <n> · Act <who> <what> · #<change>`, where `Hand`, `Lands`, `Pool`, `Life` and `Tax` are the calling seat's own, an empty pool reads `{}`, and `Act` may end with a time asked (TOOL-090).
- [x] **TOOL-058**: While the calling seat of a contested game has two commanders, the status line shall show `Tax` as one number per commander separated by `|`, and shall order the `|` groups of both `Cmdr` and `Tax` by the commanders' names, as a goldfish game's line does.
- [x] **TOOL-059**: A contested game's status line shall never end with ` · CHOICE pending`: a waiting pending choice is shown by `Act`, which names the seat it is addressed to and the choice's kind.
- [x] **TOOL-042**: In a contested game's status line, `T<turn>` shall be the number of turns the calling seat has begun, not the table turn number, and `(S<active>)` shall name the active seat by seat number.
- [x] **TOOL-043**: In a contested game's status line, `You S<n>` shall give the calling seat's seat number.
- [x] **TOOL-044**: A contested game's status line shall show one `S<n> <life>` group for each seat other than the calling seat, in ascending seat number (for calling seat 3 of four: `S1`, `S2`, `S4`), with `out` in place of the life of an eliminated seat.
- [x] **TOOL-045**: In a contested game's status line, `Cmdr` shall show the combat damage the calling seat's commander has dealt to each other seat, one number per `S<n> <life>` group and in the same order, separated by `/`, an eliminated seat keeping its number so that positions match the life groups; while the calling seat has two commanders it shall show one such group per commander separated by `|`.
- [ ] **TOOL-093**: In a contested game's status line, `Cmdr taken` shall show the combat damage the calling seat has taken from each other seat's commanders (the commanders of that seat's deck, whichever seat controlled them when they dealt it), one entry per `S<n> <life>` group and in the same order, separated by `/`, an entry being one number for a seat with one commander and, for a seat with two, two numbers separated by `|` in that seat's commanders' name order (`Cmdr taken 3/0|12/9`), and an eliminated seat keeping its entry so that positions match the life groups.
- [x] **TOOL-046**: A contested game's status line shall show `Stack <n>`, the number of items on the stack, only while the stack is not empty.
- [x] **TOOL-047**: In a contested game's status line, `Act` shall name the seat to act (the seat whose call the game is waiting on), as `you` when it is the calling seat and as `S<n>` otherwise, followed by one word for what that seat is asked, for example `Act you respond`, `Act S3 blocks`, `Act S2 turn`.
- [ ] **TOOL-090**: In a started contested game's status line, when the seat to act is not the calling seat and the outcome's game summary holds a time asked (APP-094), `Act` shall end, after its one word (TOOL-060), with a space and the time asked in parentheses, in the format of TOOL-091 (`Act S3 blocks (4 min)`); when the calling seat is the seat to act, or the summary holds no time asked, `Act` shall have no time.
- [ ] **TOOL-091**: A time asked shall be written as its whole seconds followed by ` s` when it is under 60 seconds (`45 s`, `0 s`), and otherwise as its whole minutes, rounded down, followed by ` min` (`4 min`, `75 min`).
- [x] **TOOL-060**: The word after the seat in a started contested game's `Act` shall be exactly one of: the kind of the waiting pending choice the seat must answer (`look`, `search`, `hand`, `ask`, `resolve` or `blocks`); `trigger` when a reminder waits for it as a seat other than the active seat; `respond` when a response window is asking it; `turn` when it is the active seat and none of the others holds, whatever the step and whether or not a discard is owed.
- [x] **TOOL-061**: The sentence that says what a seat is asked, in the first event line of TOOL-040 (`You are asked to ...`) and in the `ERROR` summary of TOOL-050 (`S<n> is asked to ...`), shall be, by the `Act` word of TOOL-060: for `respond`, `respond to <stack item id>` in a `stack` response window (the event line adding `: <source> from S<controller>`), `respond to the attack` in an `attack` window and `respond in the end step` in an `end` window; for `trigger`, `record or pass the <step> trigger of <card names>`; for a pending choice, `answer the <kind> choice`; for `turn`, `take its turn` (`take your turn` to the seat itself); and during mulligans `keep or mulligan`.
- [ ] **TOOL-048**: While a contested game has no step because seats are still taking mulligans, the status line shall read `Mulligan <k> · Hand <n> · Act <seats> · #<change>`, where `<k>` and `<n>` are the calling seat's mulligans taken and hand size and `<seats>` names every seat that has not yet kept, in ascending seat number, separated by single spaces, the calling seat as `you` and every other as `S<n>`, with no word after them, only the time asked of TOOL-092 when there is one (`Mulligan 1 · Hand 7 · Act you S3 · #4`).
- [ ] **TOOL-092**: While a contested game is in status `mulligan`, when the calling seat has kept and the outcome's game summary holds a time asked (APP-094), the seats listed after `Act` shall be followed by a space and the time asked in parentheses, in the format of TOOL-091 (`Mulligan 0 · Hand 6 · Act S2 S3 (2 min) · #5`).
- [x] **TOOL-049**: While the calling seat of a contested game is eliminated, the status line of its responses shall begin with `Out · `, which comes after the `Ended (<result>) · ` of TOOL-021 once the game has also ended (`Ended (win) · Out · T6 ...`).
- [x] **TOOL-062**: While a contested game's status is `ended`, its status line shall be the line of TOOL-041, or of TOOL-048 when the game ended during mulligans, after the `Ended (<result>) · ` prefix, with the `Act` field and the `Stack` field left out, no seat being asked and the stack having been discarded.
- [ ] **TOOL-063**: When `wait` returns on timeout, the response's summary shall read `OK Still waiting: ` followed by the seat to act and what it is asked in the wording of TOOL-061, then, when the timed-out event holds a time asked (APP-096), ` (for <time>)` with the time in the format of TOOL-091, then `.` (`OK Still waiting: S3 is asked to respond to s4 (for 4 min).`), and during mulligans shall name every seat still to keep, two as `S1 and S3 are` and more as `S1, S2 and S3 are` (`OK Still waiting: S1 and S3 are asked to keep or mulligan (for 2 min).`).
- [x] **TOOL-050**: When a call to a contested game comes from a seat that may not make that call now because it is not the seat to act, the `ERROR` summary shall name the seat to act by seat number, say what that seat is asked, and suggest calling `wait`, for example `ERROR Not your seat's call: S3 is asked to respond to s4. Call wait to be told when it is yours.`
- [x] **TOOL-051**: A text response to a seat of a contested game, its `get_state` listing included, shall be rendered from the outcome's game summary for that calling seat alone, and so shall show no card of another seat's hand and no card of any library.
- [x] **TOOL-066**: In a contested game's `get_state` listing, a permanent whose controller is not its owner shall be listed on its controller's battlefield with ` (owner S<n>)` after its name, and a permanent its controller owns shall carry no owner mark.
- [x] **TOOL-074**: In a contested game's `get_state` listing, when pending choices are addressed to the calling seat, the listing shall end, before the payments of `detail` `full`, with a line `Your pending choices (<n>):` followed by one line for each such choice in the order they will be answered, reading `<choice id> (<kind>)` and then what it asks: `: revealed <name> (<instance id>), ...` for `look`, `search` and `hand`; ` from S<n>: <text>` for `ask`; `: attacked by <name> (<instance id>), ...` for `blocks`; and `: <stack item id> <source> holds delta <delta> and goes to <destination>` for `resolve`, followed by the error that kept the item from resolving as held, if any.
- [x] **TOOL-079**: In a contested game, wherever a `blocks` pending choice lists the attackers a seat may block (the `CHOICE` event line that creates it, and its line in the `get_state` listing of TOOL-074), an attacker the game holds evasion for shall be shown as `<name> (<instance id>, <evasion>)`, its evasions written `flying`, `horsemanship` and `can't be blocked`, in that order, each once whether read, listed in `evasion` or both, and separated by commas, and an attacker with none as `<name> (<instance id>)`.
- [x] **TOOL-075**: The `Contested games:` part of the `get_state` description shall say that the listing includes the pending choices addressed to the calling seat, with what each reveals to it or asks of it.
- [ ] **TOOL-094**: A move event line shall begin `Moved <card>: <zone left> → <zone entered>`, followed by any note on the move and a full stop as before, and in a contested game a zone the event names a seat for (PLAY-144, PLAY-145, PLAY-146) shall read `S<n>'s <zone>` (`Moved Sol Ring: S2's graveyard → battlefield.`), in the calling seat's response and in every digest line alike, the reading seat's own zones included.
- [ ] **TOOL-095**: When `get_state` answers `card` (GAME-186), the response shall give, after the summary `Rules text of 1 card.` or `Rules text of <n> cards.` (tokens counted among the cards), for each card in turn, with no blank lines, a line holding its first face's name, then a space and its mana cost when it has one, then ` · ` and its type line, then a space and `<power>/<toughness>` when it has them, followed by each line of that face's rules text on its own line indented by two spaces, and then each further face the same way with its first line beginning `// ` (`Sol Ring {1} · Artifact`, `Forest · Basic Land — Forest`, `// Tibalt, Cosmic Impostor {5}{B}{R} · Legendary Planeswalker — Tibalt`).
- [ ] **TOOL-096**: When `get_state` answers a token in `card` (GAME-188), the response shall give it on one line as `<name> token · <types>`, followed by ` <power>/<toughness>` when it has them, ` · makes <mana>` when it produces mana (each mana string it produces, separated by ` or `), and ` · no rules text held` (`Treasure token · Artifact — Treasure · makes {W} or {U} or {B} or {R} or {G} · no rules text held`).
- [ ] **TOOL-097**: When `get_state` refuses an instance id in `card` because it names a card in the calling seat's own library (GAME-194), the `ERROR` summary shall read `ERROR <instance id> is in your library; ask for a library card's rules text by name.`
- [x] **TOOL-067**: When a call to a contested game gives an instance id of a card in another seat's hand or library (GAME-157), the `ERROR` summary shall read `ERROR <instance id> is in a hidden zone of S<n>.`, followed, for a delta, by the hint that other seats' hands and libraries are reached through `ask`, and shall name neither the card nor which of the two zones holds it.
- [x] **TOOL-068**: When a card name given in a contested game matches nothing the calling seat may see (GAME-156), the `ERROR` summary shall be word for word the same whether or not another seat holds a card of that name in its hand or library.

## MCP details

- [x] **TOOL-027**: In every game, when a response's status is `ERROR`, the MCP result shall set its error flag; when the status is `OK`, `REJECTED` or `CHOICE`, it shall not.
- [x] **TOOL-028**: If a tool call's arguments are missing, of the wrong type or otherwise malformed, then the MCP adapter shall respond in the text `ERROR` format rather than with a protocol-level fault, and a call record shall be stored for the call. An argument name the tool does not have is malformed. A call naming a tool that does not exist is answered as a protocol error.

## Player brief

- [x] **TOOL-029**: The repository shall carry one player brief for every seat of every game, a Claude Code subagent definition at `.claude/agents/goldfish-player.md`, that restricts the subagent to the `goldfishing` server's tools.
- [x] **TOOL-030**: The player brief shall instruct the subagent, for every game, to play as a strong player aiming to win as fast as the deck can, make every decision itself, give a `reason` on non-obvious plays, use `expect` on plays where it is tracking a number closely, pass `after` on every changing call, resolve or consciously pass reminders, end the game with `end_game` and a verdict, and return the game id, seed and verdict.
- [ ] **TOOL-104**: The player brief shall instruct the subagent, for every game, to read a card's rules text with `get_state` and `card` whenever it is unsure what the card does, rather than relying on memory.
- [ ] **TOOL-105**: The player brief shall instruct the subagent, for every game, to apply the legend rule itself, which the service does not: when it controls two legendary permanents with the same name, it chooses one and puts the other into its owner's graveyard with `effect`.
- [x] **TOOL-052**: The player brief shall state that the subagent is given a deck id or a deck list to load, and optionally a seed and a turn limit, or instead, for a contested game, a seat id and which seat it plays.
- [x] **TOOL-053**: The player brief shall have a section on contested games instructing the subagent to: play its seat to win unless its instructions give it another goal; call `wait` whenever its seat is not the seat to act and act on what `wait` returns; read the digest at the top of each response; respond with `play` or `effect` when asked and it has something worth doing, and `pass` otherwise; answer pending choices addressed to it, including blocks and decisions other seats' effects ask of it; and, when attacking, state what happens to the creatures with `effect` and `immediate: true` after blocks.
- [x] **TOOL-072**: The player brief's section on contested games shall instruct the subagent, when it states the result of combat with `effect` and `immediate: true`, to leave out the combat damage dealt to seats, which the service deals itself, and, once blocks are known and before advancing to combat damage, to state with `attack` and `trample` the damage each blocked attacker with trample deals past its blockers, since a blocked attacker otherwise deals the seat nothing.
